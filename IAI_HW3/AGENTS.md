# HW3 最高優先工作規範

目的：遵守作業要求、節省 token、避免沒有明確目的或重複既有成果的工作。

## 1. 必讀與適用範圍

- **任何 HW3 工作開始前，先完整閱讀本文件。** 新任務、恢復中斷、上下文重建或本文件更新後都適用；同一連續工作中，內容未變不必在每個工具呼叫前重讀。
- 適用於 `IAI_HW3/` 全部內容，也適用於從其他目錄執行的 HW3 指令。除使用者明確擴大範圍外，變更限於 HW3。
- 本文件為 **HW3 專案文件中的最高優先規範**，優先於 README、工作計畫、歷史報告及封存文件；不得以歷史「下一步」覆蓋它。它不能凌駕系統／開發者指示；當次使用者指示若明確修訂工作規範，據此更新，不自行把「追求高分」解讀為放寬作業要求。
- 發現與課程原文衝突時，以明確課程要求為合規依據，指出衝突並修正文檔；規則不明時，只暫停受影響操作，繼續可獨立完成的工作。不得為了繼續執行而自行刪減本規範。
- 從 repository 根目錄開始的新對話，不假設子目錄規範已自動載入；先明確讀取 `IAI_HW3/AGENTS.md`。以 HW3 為工作目錄可使它位於指示探索路徑；參見 [官方 AGENTS.md 說明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。

## 2. 作業紅線與必要要求

依已核對的 [HW3.pdf](docs/HW3.pdf) 第 9、14 頁；完整交件要求見 [課程要求與清單](docs/HW3_Work_Plan.md)。以下不得為追分而違反：

| 規則 | 執行限制 |
|---|---|
| 唯一允許的基底為 `google-bert/bert-base-uncased` | 不換模型家族，也不改用其他已微調的模型作基底。 |
| 僅使用課程提供資料切出的 train／validation 訓練與驗證 | 不拿 benchmark 或任何額外資料訓練；不以蒐集／猜測 benchmark 標籤補入訓練。 |
| 禁止偽造模型預測結果 | CSV 必須來自記錄清楚的模型推論或集成，不手改個別答案；分數、測試、實驗與平台提交狀態必須有證據。 |
| 禁止抄襲程式或結果 | 不把他人成果冒充自行完成；方法參考保留來源，不能以引用合理化抄襲。 |
| 最多集成 3 個模型 | 不建立超過上限的交件集成。 |
| 自行設計前處理、組建訓練管線，保存每 epoch 訓練與驗證曲線 | 變更後仍須能重現設定、checkpoint 與預測，保留必要程式、依賴及曲線。 |

**專案防錯規則，與講義明文禁令分開看待：** 不以 leaderboard 逐筆猜答案或反覆微調門檻；不讓重複文字跨 train／validation；不把訓練集表現稱為驗證結果。全 9,000 筆重訓是否允許尚未有明確依據，因此目前不執行，不能宣稱講義已明文禁止或允許。

## 3. 動手前先確定目的，查重後才執行

1. 用一至三句交代：**本次目的、沿用的成果、必要的新差異、完成條件**。簡單任務寫在進度訊息即可，不另造計畫文件。
2. 只讀與任務有關的入口：操作看 [README](README.md)；實驗查重先看 [總表](docs/Experiment_Results.md)／[registry](experiments/registry.json)；研究方向看 [最新計畫](docs/Target_92_Plan.md)。只在需要細節時讀對應報告、程式區段或原始講義頁面。
3. 判斷「已完成、未完成、缺證據」；已有結果先沿用。需要重跑時，明確寫出理由：輸入／程式已變、既有產物缺失／損壞、必要回歸驗證，或預先規劃的穩定性對照。不能只因新對話、忘記進度或想再確認而全量重做。
4. 新實驗必須先有**假設、對照、唯一主要變因、預期提供的決策資訊、訓練次數／時間上限、停止條件**，記在現有計畫或該輪報告。受控重跑也須有目的；不得只換名稱重跑相同設定。
5. 「整理／評估／寫文件」不等於要求啟動完整訓練、安裝套件或提交平台。已獲授權且必要的工作直接完成，不重複索取許可；沒有需要的新證據，不擴大搜尋或開啟已暫停方向。

## 4. Token 與執行成本

- 先定位再讀取：使用 `rg`、指定檔案／行段／JSON 欄位；排除 `.venv/`、模型權重與快取，不列印整個 snapshot、資料集、長日誌或全目錄樹。
- 同一工作中沿用已讀且未變的內容；獨立讀取合併呼叫，依賴操作依序處理。輸出只保留足以作決策的摘要與錯誤。
- 已有工具能完成就沿用；沒有明確重複需求，不新增框架、通用工具、重複文件或測試。沒有使用者明確要求，不啟動額外代理。
- 驗證依變更範圍選最小充分集合：純文件修改檢查內容、連結與 diff；程式變更跑相關測試；影響模型行為才安排必要推論或訓練。通過且沒有新變更／新疑點，不反覆重跑。
- 不為了縮短回覆省略必要驗證、隱藏失敗或提前宣告完成。節省 token 的方式是減少無關工作，不是降低完成標準。
- 中斷前或交接時，在現有工作紀錄留下「已完成／未完成／下一個具體動作／關鍵產物及已用預算」；恢復後從未完成處繼續，不重新盤點一切。

## 5. 產物與狀態管理

- 開始修改前查看相關 Git 差異，保留既有未提交工作。新實驗用唯一輸出路徑，不覆寫既有 checkpoint／CSV，不為整理而刪除模型或結果。
- 候選角色與 Kaggle 回報以 registry 為準；未知分數維持 `null`，使用者回報與平台核驗分開標示。使用前核對實際 checkpoint，不能把 `saved_models/checkpoint/` 的名稱當作最佳模型證據。
- 新增／變更實驗產物或 registry 時，更新對應報告，執行 `python tools/refresh_experiments.py`，再以 `--check` 核對。純文件變更不需重算全部模型 hash。
- 詳細結果只維護在該輪報告與總表；README 保持操作入口，封存內容不當現行指令。不要複製同一組分數到多份新文件。
- 平台提交與最終封裝依交件清單辦理；沒有相應授權不代為提交。未完成乾淨解壓推論、選定版本與平台收件核對，不宣稱已交件。

## 6. 收尾檢核表：逐項通過才能宣告完成

這是每次工作重用的模板，**不要把本文件永久勾成通過**。本次工作紀錄或最後回覆需留下檢核結果；每項填「通過＋簡短證據」或「不適用＋理由」。不適用必須確實與本次範圍無關，不能用來跳過失敗或未做的必要工作。

- [ ] **規範與範圍**：已讀本文件；變更限於已授權範圍，未違反作業紅線，未把不確定規則當成已確認事實。
- [ ] **目的完成**：本次產物滿足開始時的目的與完成條件；沒有把後續計畫或部分進度稱為完成。
- [ ] **查重與成本**：已沿用相關既有成果；每次新增／重跑有理由，未做無關搜尋、重複驗證或無目的訓練。
- [ ] **既有工作保全**：相關 diff 已檢視，沒有覆蓋使用者修改、原始資料或既有模型／預測。
- [ ] **驗證證據**：與變更相稱的檢查已通過；記下實際命令／結果或文件檢查範圍，未執行的項目沒有冒稱通過。
- [ ] **實驗可追溯**：如涉及實驗，設定、資料／切分、模型、指標與 CSV 對應一致；必要的報告、registry／snapshot 已更新且核對通過。
- [ ] **文件與狀態**：相關入口與連結有效，已完成／待辦／未知清楚區分；新資訊有唯一維護位置。
- [ ] **交付誠實**：最後回覆簡述完成項、驗證與必要限制；如有剩餘必要工作，清楚列出，未宣稱整個任務完成。

**收尾判定：所有適用項通過才可宣告完成。** 任一項失敗先修正再核對；若需外部資訊／權限或無法繼續，僅回報「尚未完成」、原因、已保留成果及下一步，不為通過檢核而捏造證據或無限重試。

簡短收尾格式：`檢核：適用項 X/X 通過；不適用：項目與理由。證據：檢查／產物路徑。`
